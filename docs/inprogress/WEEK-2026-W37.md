## 4. ✅ libc bugs found and fixed this week — all HW-verified, all with tests

- **`strncmp`/`strncasecmp` read one byte past `n`** (libphoenix **`f2d2789`**, tests **`a82e0e4`**
  + **`7c80324`**). The bound was tested *after* `*p`, so a string ending exactly at a page boundary
  faulted — it was killing SuperTuxKart in AngelScript's tokenizer. `strncasecmp` had **no** test
  coverage at all. Negative control: the same pattern faulted on the old code, so the test is not
  vacuous. Manifest `2026-09-10-strncmp-over-read-fix.md`.
- **`getaddrinfo` leaked and lied** (**`75bf050`**, test **`fc3dd0f`**): on a failed `realloc` it
  leaked the old buffer *and* returned 0 with `*res == NULL`. It had zero coverage; the new test is
  DNS-free so it runs anywhere.
- **`_atexit_init` dereferenced NULL** (**`160e916`**): the list head came from a file-scope compound
  literal, leaving no named storage to recover to; it is now a named static. This was the "2070
  exceptions in ntpclient" report — ntpclient was innocent (it is `psh` under an applet name).
  ⚠ The ELF is *correct* (`.data` holds `0x4373e0`), so a runtime NULL meant **`.data` did not reach
  the process intact** — a load-time failure that would hit **any** statically initialised pointer.
  ✅ **2026-09-12: the recovery no longer masks it, and it is not happening now.** The fix recovered
  **silently**, hiding the only evidence the corruption still occurred; `_atexit_init` now reports it
  (libphoenix **`94a2d8e`**). Measured with the reporter live: **~3645 processes across three boots**
  (2500 + 1000 + 85 launches plus boot processes), every child reaching `main()`, **0 reports, 0
  faults**. ⚠ Not proof it is fixed — the check covers **one word**, and kernel `6cd3adec`'s
  premature-EOF diagnostic never fired either — but it bounds the current rate, and a recurrence can
  no longer pass unnoticed. Tracked as `atexit-null-head`.
- ✅ **Regression-checked twice: 541 libc tests, 0 failures**, with zero spurious instrument fires.

## 5d. ★★★ `premain-hang` LOCALISED — the process never reaches libc at all

**The fault is BEFORE `_libc_init`**, i.e. in **exec / program loading (kernel side)** or psh's spawn
path — not in a libc initialiser, which is where three weeks of this hunt had been pointed.

**Evidence (sound this time).** 30 cold `quakespasm -loadbench` launches, one per boot, on a build
carrying the one-marker `LIBC_STARTUP_TRACE=min` instrument (verified in the **live NFS export**, not
just the buildroot — `--scope core` does not relink ports). **25 reached readiness in ~2 s; 5 produced
literally nothing in a 300 s window** — no app output and **zero `libc-init: enter` markers after the
command echo**, against exactly 1 in every one of the 25 healthy trials. 300 s clears the documented
~68 s cold-exec class by 4×, so this is a hang, not a slow load.

⚠ **RETRACTION, and it is a big one.** The **"cold boot + heavy launch" trigger grid** (p = 4.4e-04)
and the **"reproduced on QuakeSpasm, 2 in 23"** claim are **withdrawn**. Every silent-shaped trial in
the entire artifact history — five, across four benches — ran a **~45 s** post-command window, which
is *below* the ~68 s cold-exec class, so "printed nothing" and "had not finished loading" were the
same observation. My own memory carried that warning (`--idle-secs` ≥ 240) and I ran 45 s anyway.
ⓘ Two long-window observations are **not** affected and still stand: the original event (idle 240 /
max 300) and the spawn-storm stall (≥218 s).
ⓘ Rate is now **5/30 ≈ 17%**, well above the ~4% quoted before; the two are not comparable, since the
old detector could not separate a hang from a slow start.

🐞 **Four measurement defects found and fixed** — all of them would have produced a confident wrong
answer, in both directions:
- the window was read from arrival stamps, which cannot measure a wait in which nothing arrived — a
  genuine 300 s hang would have scored *inconclusive*. `psh-interact` now writes
  `*** capture-window ended after N.Ns` into the log itself, and `check-capture-complete.py` ignores
  that line (counting it would mark every silent run "CAPTURE OK").
- `--stamp` splits the capture mid-token, so a healthy trial's `libc-init: enter` arrived as `libc` +
  `-init: enter` and graded as reaching neither libc nor main.
- markers were counted over the whole log — a boot prints ~20 of them, which would have scored a
  silent launch as "reached libc" on the strength of the boot's own output.
- a trial whose command was never **echoed** never launched anything; counting it as an event is what
  made a 2-in-23 bench read as 3-in-24.
✅ All of it is now in `scripts/classify-premain-trials.sh`, controlled **both ways** against real logs
(`c76187c48`, `edf8f71e6`, `0c2a7ef8b`, `ed1bb3856`, `c8df8c79f`).
⏳ Confirmation bench running with the window marker live, so the proof sits in the artifact rather
than in my reading of a side log.
Detail: [`docs/misc/2026-09-13-premain-hang-condition-grid.md`](../misc/2026-09-13-premain-hang-condition-grid.md).
